📚 Como implementar Mocks em Kotlin

🎯 O que faz

Intercepta chamadas de saída do serviço para APIs externas via WebClient. Quando habilitado, o serviço não faz a chamada HTTP real — retorna direto o payload do MongoDB.

⚙️ Pré-requisitos

Ative no application-local.yml:

mocks:
  webclient:
    enabled: true
📝 Como o ID do mock é gerado

O filtro intercepta automaticamente qualquer chamada feita via WebClient e usa MÉTODO:/caminho como chave de busca no MongoDB.

// O filtro captura assim internamente:
val endpointId = "${request.method().name}:${request.url().path}"
// Exemplo: "GET:/v1/products/stock-status"
🔧 Implementação do Client

Nenhuma mudança necessária no client existente. O MockWebClientFilter é injetado automaticamente no AbstractWebClient.

@Service
class ProductStockClientImpl(
    @Value("\${client.catalog.url}")
    private val url: String
) : AbstractWebClient(url) {

    override fun mapError(response: ClientResponse): Mono<ClientResponse> { ... }

    fun getStockStatus(productId: String): ProductStockDto {
        return getClient(WebClientConstants.CONTENT_TYPE_APPLICATION_JSON)
            .get()
            .uri("/v1/products/stock-status?productId=$productId")
            .retrieve()
            .bodyToMono(ProductStockDto::class.java)
            .block()!!
    }
}

⚠️ Atenção

O _id deve ser exatamente igual ao método HTTP + caminho da URI chamada pelo WebClient, sem query params.

🎯 O que faz

Retorna payloads diferentes por usuário específico. O client injeta GetExternalMockById e consulta o MongoDB antes de fazer a chamada real.

⚙️ Pré-requisitos

Nenhuma configuração extra no yml. A busca usa a collection mocks com query por externalMockProperties.endpointId + allowedUsers.

📝 Implementação do Client

Crie uma implementação mock que injeta GetExternalMockById e use @ConditionalOnProperty para ativá-la em ambiente local:

// Interface do client
interface OrderPricingClient {
    fun getPricing(orderId: String): OrderPricingDto
}

// Implementação real
@Service
@ConditionalOnProperty("mocks.pricing.enabled", havingValue = "false", matchIfMissing = true)
class OrderPricingClientImpl(
    @Value("\${client.pricing.url}") private val url: String
) : OrderPricingClient, AbstractWebClient(url) {

    override fun getPricing(orderId: String): OrderPricingDto {
        return getClient(WebClientConstants.CONTENT_TYPE_APPLICATION_JSON)
            .get()
            .uri("/v1/orders/pricing?orderId=$orderId")
            .retrieve()
            .bodyToMono(OrderPricingDto::class.java)
            .block()!!
    }
}

// Implementação mock
@Service
@ConditionalOnProperty("mocks.pricing.enabled", havingValue = "true")
class OrderPricingClientMock(
    private val getExternalMockById: GetExternalMockById
) : OrderPricingClient {

    override fun getPricing(orderId: String): OrderPricingDto {
        return getExternalMockById.execute(
            endpointId = "GET:/v1/orders/pricing",
            userIdentifier = orderId,
            clazz = OrderPricingDto::class.java
        ) ?: throw MockNotFoundException(orderId, "GET:/v1/orders/pricing")
    }
}
⚙️ yml local
mocks:
  pricing:
    enabled: true
🔍 Como o MockRepository consulta o MongoDB

O GetExternalMockByIdImpl usa o MockRepository que faz a seguinte query na collection mocks:

// Query executada internamente
{
  "externalMockProperties.endpointId": "GET:/v1/orders/pricing",
  "externalMockProperties.allowedUsers": { "$in": ["order-001"] },
  "enabled": true
}

// Implementação real do repositório
@Repository
interface MockRepository<T> : MongoRepository<Mock<T>, String> {

    @Query(
        "{ " +
        "  'externalMockProperties.endpointId': ?0, " +
        "  'externalMockProperties.allowedUsers': { '\$in': [ ?1 ] }, " +
        "  'enabled': true " +
        "  } "
    )
    fun findExternalMockByEndpointIdAndAllowedUsersContainsAndEnabledTrue(
        endpointId: String,
        userIdentifier: String
    ): Mock<T>?

    fun findMockByIdAndEnabledTrue(id: String): Mock<T>?
}

O userIdentifier passado é o identificador do recurso (ex: orderId) — ele precisa estar na lista allowedUsers do documento MongoDB para o mock ser retornado.

⚠️ Atenção

O endpointId em externalMockProperties deve ser idêntico ao valor passado na chamada getExternalMockById.execute(endpointId = ...) no client mock.

🎯 O que faz

Intercepta requisições recebidas pelo próprio serviço. O cliente envia o header X-MOCK-ID e recebe o payload cadastrado no MongoDB — sem executar nenhuma lógica de negócio.

⚙️ Configuração

O MockInterceptor já está ativo em todos os perfis exceto production via @Profile("!production"). Nenhuma configuração adicional necessária.

// Já existe no projeto — nenhuma mudança necessária
@Component
@Profile("!production")
class MockInterceptor(
    private val getInternalMockById: GetInternalMockById,
    private val objectMapper: ObjectMapper
) : HandlerInterceptor {

    override fun preHandle(
        request: HttpServletRequest,
        response: HttpServletResponse,
        handler: Any
    ): Boolean {
        val mockHeader = request.getHeader("X-MOCK-ID") ?: return true
        val mock = getInternalMockById.execute(mockHeader) ?: return true
        response.status = 200
        response.contentType = "application/json;charset=UTF-8"
        response.writer.write(objectMapper.writeValueAsString(mock))
        return false
    }
}
📝 Como usar

Cadastre o mock no MongoDB com qualquer _id e envie o header na requisição:

// Exemplo via curl
curl -X POST http://localhost:8080/my-service/checkout \
  -H "X-MOCK-ID: checkout-mock" \
  -H "Content-Type: application/json" \
  -d '{"orderId": "order-001"}'

// Exemplo via RestTemplate / WebClient no teste
webClient.post()
    .uri("/checkout")
    .header("X-MOCK-ID", "checkout-mock")
    .bodyValue(request)
    .retrieve()
    .bodyToMono(CheckoutResponseDto::class.java)

🔍 Como o MockRepository consulta o MongoDB

O GetInternalMockByIdImpl usa o MockRepository buscando pelo _id do documento com enabled: true:

// Implementação real
@Component
class GetInternalMockByIdImpl(
    private val mockRepository: MockRepository<*>
) : GetInternalMockById {
    override fun execute(id: String): Any? {
        return mockRepository.findMockByIdAndEnabledTrue(id)?.payload
    }
}

// Query executada internamente
// db.mocks.findOne({ _id: "checkout-mock", enabled: true })
// Retorna apenas o campo "payload" do documento

O valor do header X-MOCK-ID enviado pelo cliente deve ser exatamente igual ao _id do documento no MongoDB.

⚠️ Atenção

O interceptor retorna o payload inteiro do campo payload serializado como JSON. Para GraphQL, estruture o payload com data.nomeQuery conforme o contrato.
